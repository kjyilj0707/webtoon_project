02개념 정리

Git 개념 — commit과 push

웹툰 프로젝트를 GitHub(kjyilj0707/webtoon_project)에 연결하면서 정리한 핵심 개념입니다.

Working Dir add → Staging commit → Local Repo push → GitHub (origin)

Commit — 로컬에 남기는 저장 지점

지금 이 순간의 파일 상태를 하나의 스냅샷으로 남기는 것. 인터넷 연결 없이도 가능하며, 실수해도 이전 커밋으로 되돌릴 수 있는 안전망 역할을 합니다.

Push — 원격 저장소로 업로드

로컬에만 있던 커밋들을 GitHub 같은 원격 저장소로 올려서 백업·공유하는 것. push해야 비로소 다른 컴퓨터나 서버가 내 코드를 받아볼 수 있습니다.

💡

.gitignore와 .env — API 키 같은 민감 정보는 .env에 담고 git 추적에서 제외합니다. 대신 어떤 변수가 필요한지 양식만 보여주는 .env.example을 올려서, 다른 사람(미래의 나 포함)이 무엇을 채워야 하는지 알 수 있게 합니다.

03실습 완료

데이터베이스 실전 구성 — SQLite

CSV 대신 실제로 SQL 쿼리가 가능한 로컬 DB를 만들어봤습니다.

Python
import sqlite3
import pandas as pd

df = pd.read_csv('webtoon_clean.csv')
conn = sqlite3.connect('webtoon.db')
df.to_sql('webtoons', conn, if_exists='replace', index=False)
conn.close()

to_sql()이 CSV의 컬럼 타입(int64 → INTEGER, float64 → REAL 등)을 보고 SQL 테이블 스키마를 자동으로 만들어줍니다.

✓ webtoons 테이블에 27개 컬럼, 3,846행 저장 확인 (titleName, viewCount, favoriteCount 등)
💡

SQLite를 먼저 써본 이유는 서버 설치 없이 파일 하나로 DB 개념(테이블·쿼리)을 실습할 수 있기 때문입니다. 이후 클라우드로 옮길 때 Firestore로 자연스럽게 이어집니다.

Firebase 프로젝트 연결

로컬 DB를 넘어, 인터넷 어디서나 접근 가능한 클라우드 DB로 Firestore를 선택했습니다.

진행한 단계

  1. Firebase 콘솔에서 프로젝트 생성 → 프로젝트 ID wtproject-5a00f
  2. Firestore Database 활성화 (테스트 모드, 서울 리전)

키 파일은 DB 전체를 조작할 수 있는 마스터키급 권한을 가지므로, .gitignore에 아래 항목을 추가해 git에 절대 올라가지 않도록 했습니다.

05완료

Firestore에 데이터 업로드

firebase_migrate.py 스크립트로 webtoon_clean.csv 전체를 클라우드로 옮겼습니다.

firebase_migrate.py (핵심 부분)
batch = db.batch()
for _, row in df.iterrows():
    doc_ref = collection_ref.document(str(row["titleId"]))
    batch.set(doc_ref, row.to_dict())
    count += 1
    if count % 400 == 0:      # Firestore 배치 쓰기 한도(500건) 안에서
        batch.commit()        # 400건씩 묶어서 커밋
        batch = db.batch()
💡

한 건씩 업로드하면 3,846번 개별 요청을 보내야 해서 느립니다. 배치(batch)로 여러 건을 묶어 한 번에 커밋하면 훨씬 빠르고 안정적입니다.

✓ 3,846건 전체 업로드 완료. 조회수 1위 검증: 마음의소리 — 2,593,260,741

07개선

"더 보기" 기능 추가

처음엔 상위 100개만 보이도록 만들었는데, 이유를 묻는 질문을 계기로 페이지네이션을 붙였습니다.

💡

Firestore는 문서를 읽을 때마다 비용/한도가 소모됩니다. 3,846건을 한 번에 다 불러오면 느리고 낭비가 커서, 처음엔 limit(100)으로 제한했습니다.

이후 Firestore의 startAfter 커서 개념을 이용해 "더 보기" 버튼을 누를 때마다 다음 100개씩 이어서 불러오도록 개선했습니다. 커서는 "마지막으로 읽은 문서"를 기억해뒀다가, 다음 조회 때 그 지점부터 이어 읽는 방식입니다.

app.js (핵심 부분)
const q = lastDoc
  ? query(col, orderBy(sortField, "desc"), startAfter(lastDoc), limit(100))
  : query(col, orderBy(sortField, "desc"), limit(100));
08트러블슈팅

오늘 만난 문제와 해결 과정

실습에서 가장 많이 배우는 부분은 사실 에러를 해결하는 과정입니다. 오늘 겪은 네 가지를 정리합니다.

1. pip이 통째로 빠져있던 파이썬

No module named pip → python -m ensurepip --upgrade로 pip 자체를 복구.

2. PowerShell이 firebase 명령을 거부함

npm으로 설치한 CLI는 .ps1 스크립트로도 동작하는데, PowerShell의 기본 보안 정책이 스크립트 실행을 막았습니다. 처음엔 firebase.cmd로 우회했고, 이후 사용자 요청으로 정책 자체를 변경했습니다.

PowerShell (관리자 권한 불필요, 내 계정에만 적용)
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

3. "세션 ID"와 "인증 코드"를 혼동

firebase login --no-localhost 흐름에서 화면에 뜨는 세션 ID(예: F5A25)를 인증 코드란에 그대로 입력해 실패. 실제 인증 코드는 브라우저에서 로그인을 마친 뒤에만 발급됩니다.

4. 인증 코드 만료

두 번째 시도에서는 코드 형식은 맞았지만(4/0AXEQ...) 시간이 지체돼 만료된 것으로 추정. 결국 코드를 손으로 옮기지 않아도 되는 일반 firebase login(로컬 브라우저 자동 콜백 방식)으로 전환해 성공.

🗑️

덤으로 발견한 것: 32MB짜리 node-v24.18.1-x64.msi 설치 파일이 프로젝트 폴더에 방치돼 있었습니다. git에 잡히기 전에 .gitignore에 *.msi를 추가해 제외했습니다.
